# chot-ink 職務経歴書生成

`README.md`（五十嵐翔のプロフィール／経歴）を入力として、chot-ink の職務経歴書管理ツールに登録するための Markdown を生成する。出力は次の 2 種類:

- **A. スキル一覧** — スキルごとの実務経験期間と詳細。
- **B. 参画プロジェクト一覧** — プロジェクトごとの期間・役割・概要・担当業務・使用技術。

ユーザーの依頼に応じて両方、または片方を出力する（指定が無ければ両方）。

## 入力

1. **`README.md`**（リポジトリ直下） — 経歴の本体。会社・期間・実装内容の一次情報。
2. **`chot-ink/skill.json`**（リポジトリ直下。絶対パスは `/home/syo_igarashi/chot-ink/skill.json`） — 職務経歴書管理ツールで選択可能な**スキル名の定義**。出力する「スキル名」「使用技術」は必ずここに存在する名称から選ぶ。
   - 実体は**オブジェクトの配列**で、各要素は次のキーを持つ（2026 年時点で 216 件、うち `is_active: true` が 210 件）:
     - `skill_name`（例: `"React"`, `"Next.js"`, `"CakePHP"`） — これが出力に使う正式名称。
     - `skill_aliases`（`null` または別名の配列。例: `["Google Cloud Run functions"]`） — README の表記ゆれを吸収するためのマッチ用。
     - `is_active`（真偽値） — **`false` のスキルは選択肢に出さない**。`true` のものだけ使う。
     - その他 `id` / `category_id` / `svgl_icon_url` などは出力に使わない。
   - README の技術は `skill_name` と `skill_aliases` の両方に対して照合する（例: README の「Rails」→ `skill_name: "Ruby on Rails"` にマッチ）。
   - ファイルが大きいので、必要なら `node -e` などで `skill_name` の一覧を先に抽出してから照合するとよい。
   - このファイルが存在しない・読めない場合は、勝手にスキル名を創作せず、ユーザーに場所と内容を確認する。

## 共通ルール

### 会社名・サービス名のぼかし

- **所属・取引先の会社名、サービス名（固有名詞）は出さない。** 代わりに**業界名・ドメイン名**に置き換える（プロジェクトタイトル・概要・詳細すべてに適用）。
- 実装していた技術スタック・担当領域・成果は具体的に書いてよい（むしろ書く）。
- 社内固有のプロジェクト名・独自ライブラリ名も、必要なら一般名（例:「社内独自のフロントエンドライブラリ」）に言い換える。
- ぼかしの対応例（README の固有名詞 → 出力での表現）:

| README の記述 | ぼかした表現 |
| --- | --- |
| リクルート住まいカンパニー | 不動産・住宅情報サービス |
| イオンアイビス / セブン&アイ | 小売・流通系サービス |
| BeForward（中古車の海外販売） | 中古車の越境 EC サービス |
| マナボ / NTT ラーニングシステムズ | 教育・e ラーニングサービス |
| ジェネシスヘルスケア | ヘルスケア・医療系サービス |
| アジャイルメディア・ネットワーク | アドテク・マーケティング系サービス |
| Pococha（ライブ配信アプリ） | ライブ配信サービス |
| ランサーズ | クラウドソーシングプラットフォーム |
| Autron | 生成 AI／LLM チャットツール |

### 年月・期間の扱い

- 期間は README の年月見出し（`### 2020/9~2024/2` など）から取る。
- 月は「その月を含む」で数える（例: `2020/9~2024/2` は 2020 年 9 月〜2024 年 2 月で 3年6カ月）。
- 現在も継続中で終了月が無い場合は、期間計算では `currentDate`（会話コンテキストの今日の日付）までとし、プロジェクトの「終了年月」欄は**空欄**にする。

## A. スキル一覧

各スキルについて、以下の 3 項目を出力する。

| 項目 | 内容 |
| --- | --- |
| **スキル名** | `chot-ink/skill.json` の `is_active: true` な `skill_name` の中から選択。定義に無い技術は出力しない。 |
| **経験期間** | 所属していた会社の在籍期間から推定した実務経験期間。`Y年Mカ月` 形式。 |
| **詳細** | フリーフォーマット。実装していたものが分かるように書く。会社名は出さず業界・ドメインでぼかす。 |

### 経験期間の算出

- あるスキルの経験期間 = **そのスキルを使っていた会社の在籍期間の合計**。
  - 同一期間に複数会社を掛け持ちしていた記述があっても、期間の**重複は二重計上しない**（重なる区間はまとめて 1 回だけ数える）。
- 端数は月単位。合計月数を `Y年Mカ月` に直す（12 カ月 = 1 年）。0 年の場合は `Mカ月` のみでよい。
- README にそのスキルの使用時期が明記されておらず判断に迷う場合は、推定である旨を詳細側に一言添えるか、控えめな期間にする。誇張しない。
- **TypeScript は Next.js と同等の経験期間として扱う**（本人確認済みの恒久ルール）。README に TypeScript の明記が無くても、Next.js を使っていた会社の在籍期間の合計と同じ年数を割り当て、`(推定)` は付けない。詳細には Next.js／React を用いた画面実装で使用した旨を書く。

### 出力フォーマット（スキル）

スキルごとに以下のブロックを、経験期間が長い順（または skill.json の並び順）で並べる。

```markdown
### <スキル名>

- **経験期間**: <Y>年<M>カ月
- **詳細**:
  <実装していた内容。業界・ドメインでぼかしつつ、技術スタックと担当領域を具体的に。>
```

一覧性が必要な場合は、先頭に表形式のサマリを付けてもよい。

## B. 参画プロジェクト一覧

README の会社ごと・案件ごとの記述を、プロジェクト単位に分解して出力する。1 社の中に複数の案件（取引先・サービス）がある場合は、原則それぞれを 1 プロジェクトとして分ける。実装実績が無い相談・見積もりだけの案件（例: 要件見積もりのみで断ったもの）は、プロジェクトとして出さないか、含める場合はその旨を概要に明記する。

各プロジェクトについて、以下の項目を出力する。

| 項目 | 内容 |
| --- | --- |
| **開始年月** | `YYYY/MM` 形式。README の在籍期間・案件の記述から推定。 |
| **終了年月** | `YYYY/MM` 形式。**現在進行中の場合は空欄**。 |
| **役割** | `フロントエンジニア` / `アプリケーションエンジニア` など。担当内容から判断して 1〜複数を記載。 |
| **プロジェクトタイトル** | 業界・ドメインでぼかした簡潔なタイトル（会社名・サービス名は使わない）。例:「不動産・住宅情報サービスのスマホサイト開発」。 |
| **プロジェクト概要** | どんなサービス・システムだったかを業界／ドメインでぼかして説明。 |
| **担当業務** | 自分が担当した実装・作業を箇条書きで具体的に。 |
| **使用技術** | そのプロジェクトで使った技術。**`chot-ink/skill.json` の `is_active: true` な `skill_name` から参照した名称のみ**列挙する（skill.json に無い技術は載せない）。 |

### 役割の判断

- **フロントエンジニア**: Web フロントエンド（React / Next.js / jQuery / テンプレートエンジンでの画面実装など）が主体。
- **アプリケーションエンジニア**: サーバサイド／バックエンド（PHP・Rails・FastAPI など）やバッチ、モバイルアプリ実装など、フロントに限定されない実装が主体。
- 両方に相当する場合は両方を併記してよい。README の担当記述に忠実に判断する（誇張しない）。

### 使用技術の埋め方

1. README の各プロジェクト記述から使用技術を洗い出す。
2. それぞれを `skill.json` の `skill_name` / `skill_aliases` に照合し、**マッチした `skill_name`（active のもの）だけ**を使用技術に採用する。
3. マッチしない技術（skill.json 未登録）は使用技術欄に載せない。どうしても触れたい場合は概要・担当業務の文中で言及するに留める。
4. **Next.js または React を使用技術に含むプロジェクトには、`TypeScript` も併せて列挙する**（上記の恒久ルールに準拠）。

### 出力フォーマット（プロジェクト）

新しい（終了年月が新しい）プロジェクトを上に、時系列降順で並べる。

```markdown
### <プロジェクトタイトル>

- **開始年月**: YYYY/MM
- **終了年月**: YYYY/MM   <!-- 現在進行中は空欄 -->
- **役割**: フロントエンジニア / アプリケーションエンジニア
- **プロジェクト概要**:
  <業界・ドメインでぼかしたサービス／システムの説明>
- **担当業務**:
  - <担当した実装・作業を具体的に>
  - ...
- **使用技術**: React, TypeScript, Next.js, ...  <!-- skill.json の skill_name のみ -->
```

一覧性が必要な場合は、先頭に `| タイトル | 期間 | 役割 | 主な使用技術 |` のサマリ表を付けてもよい。

## 手順

1. `chot-ink/skill.json` を読み、`is_active: true` な `skill_name`（と `skill_aliases`）の一覧を取得する。
2. `README.md` を読み、各所属会社の在籍期間・案件・使用技術・実装内容を抽出する。
3. 依頼に応じて A・B のどちらを出すか判断する（指定が無ければ両方）。
4. **A スキル一覧**: skill.json のスキル名ごとに使用した会社・期間を突き合わせ、経験期間を算出し、詳細を書く。
5. **B プロジェクト一覧**: 案件ごとに項目を埋める。使用技術は skill.json の `skill_name` に照合した名称のみにする。
6. 「共通ルール」のぼかしを全体に適用し、出力フォーマットに従って Markdown を出力する。

## 注意

- skill.json に無いスキル名・技術は出力しない（ツール側で選択できないため）。
- 会社名・サービス名の固有名詞が出力に混ざっていないか、生成後に必ず自己チェックする。
- 期間・役割・担当業務の根拠が README から辿れる形になっているか確認する（誇張・断定を避ける）。
- 進行中プロジェクトの終了年月は空欄にする。
